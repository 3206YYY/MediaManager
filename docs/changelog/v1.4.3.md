# v1.4.3 — 修掉点不开的东西，让报错能被定位

## 这一版为什么存在

发完 v1.4.2 之后做了一次「站在反方挑毛病」的自查，被指出了三件不太体面的事：

1. 日记里的附件缩略图**点不开** —— 它长得像功能，点上去毫无反应，比不显示还糟；
2. 程序报错时只说「请把 logs 目录发给开发者」，可**用户不知道 logs 在哪**，也没有按钮，
   最后只能去评论区留一句「打不开，好卡」；
3. 极简模式存在，但**默认关**、开关埋在设置第一页，等于没有；而且它叫「极简」，
   实际还留着新建标签按钮 —— 跟「分类已被藏起来」自相矛盾。

这一版只做这三件事和一个产品决定，**不加任何新功能**。

---

## 一、日记附件点不开（真 bug）

`DiaryWindow.xaml` 里那排缩略图只有一个 `Border > Image`，**没有绑任何事件**。

修的时候顺手把「点开一个媒体」的实现收敛成一份：新增 `App/Services/MediaOpenLauncher.cs`，
分流（`MediaOpenStrategy`）+ 建窗口的代码只有这一处，主界面 / 私密空间 / 日记共用。
以前这段在两个窗口各写一遍、日记里干脆没有。

翻页范围**限定在同一篇日记的图片里**：从第二张点进去，按 → 翻到的是这一篇的下一张，
不会滑到三个月前的别的照片。

另外补了个「永远空灰框」的坑：库里 `ThumbnailPath` 为空时（清过缓存 / 导入失败 /
备份恢复），这些图以前永远不填。现在会补排缩略图生成，生成完合并 280ms 重绑一次。

## 二、报错终于能定位了

设置 → 关于与更新 → 新增「遇到问题」卡片：

- 显示**真实**的日志目录（便携模式和安装模式落点不同，不能写死）；
- 一键打开日志目录；
- 一键复制诊断信息。

诊断信息只包含版本 / 系统 / 运行时 / 数据模式 / 数据目录 / 条目数，**不读照片和日记**。
路径里的用户名自动替换成 `<用户>` —— 这个东西十有八九会被贴到公开论坛，
带着 `C:\Users\张三` 出门就是隐私泄漏。

复制出来的实际样子：

```
版本：v1.4.3
系统：Microsoft Windows 10.0.26200
运行时：.NET 8.0.31   架构：X64
数据模式：便携（数据在程序目录 Data\）
数据目录：C:\Users\<用户>\...\Data
库内媒体条目：27
```

两处全局错误弹窗也改成指向这个入口；进程要崩的那种，直接把日志路径印在弹窗里。

## 三、第一次打开先问一句

新装用户面对 9 个顶级入口，很容易以为这是「文件管理器全家桶」，而他多半只想看图。

现在首次启动会弹一个小窗，两张卡片二选一：

- **我只想看图和视频** → 侧栏只留「发现 / 全部 / 收藏 / 文件夹」，其余收起来；
- **我要整理照片、写日记** → 保留全部入口。

选完立即生效，随时能在「设置 → 界面」改回来。**不删任何功能，只是收起入口。**

两条边界写死了：

- **只在全新库上问**（没有根目录、没有媒体条目）。老用户升级时突然弹个选择框，
  会让人以为程序把库清空了 —— 这种惊吓比「侧栏有点多」严重得多。老库只静默补一个
  「问过了」的标记，不弹窗、不改用户原来的设置。
- **非模态**：主窗口已经显示出来了，用户可以先把界面看一圈再决定。
  直接按 Esc 关掉也允许，等于「不选」，保持原本的设置。

顺带把「极简」做得名副其实：标签分组（新建标签按钮 + 标签列表）以前没跟着收起，
和分类被藏掉自相矛盾，现在一起收。

## 验证

- `dotnet build`：0 警告 0 错误
- `dotnet test`：**281 通过**（已发布的 v1.4.2 是 260；其中 App 层从 0 变成 14）
- `build/verify/` 六个实机脚本全部通过：

| 脚本 | 验什么 | 结果 |
|---|---|---|
| `verify_external_open.py` | 非核心类型外放、图片视频仍走内置 | 4/4 |
| `verify_vault_password.py` | 密码全生命周期 | 20/20 |
| `verify_diary_calendar.py` | 日历深色、写回、年视图跳转 | 17/17 |
| `verify_diary_attachment.py` | 附件能点开、翻页不越界、缺失缩略图自动补 | 9/9 |
| `verify_diagnostic_info.py` | 诊断信息内容、复制、路径打码 | 11/11 |
| `verify_first_run.py` | 新装问一次 / 重启不再问 / 老库不打扰 | 30/30 |

两个新增脚本都做过**反向验证**（把修复去掉，确认会红）：

- 去掉日记附件的点击事件 → `verify_diary_attachment.py` 1 项变红；
- 把「老库静默补标记」改成永远返回 false → `verify_first_run.py` 的
  「静默补上了 Ui.FirstRunDone」变红；
- 把「按 Id 判重」删掉 → App 层单测 1 项变红。

## 已知未解决

- **视频播放器仍然没有实机脚本覆盖**，改了 `MediaOpenLauncher` 的视频分支只能人眼确认；
- App 层有 14 项测试了，但离「够用」还远（WPF 视觉树、ViewModel 状态机基本没测）；
- 内存峰值仍未测量、未优化；
- 密码仍可被改库绕过（界面里已明说）。
