# V1.3.0 图片编辑器升级说明（开发完成，待打包）

这一版把图片编辑器从「一排按钮」重做成接近美图秀秀 / Snapseed 的结构：
右侧按用途分成七个分类，每个分类里只放这一类的工具；所有编辑仍然只改副本，原图永远不动。

> 当前状态：代码已完成，`dotnet build` 0 警告 0 错误，单元测试 **148/148 通过**，
> 端到端验收脚本 `build/verify_v130.py` 通过；版本号已升到 **1.3.0**。

---

## 1. 右栏重做：分类轨 + 属性面板

原来是一条直排按钮，功能一多就分不清哪几个是一组。现在右侧固定为两部分：

- 最右是窄条分类轨，七个分类，图标 + 文字，选中高亮：
  **基础 / 裁剪 / 调色 / 文字 / 标注 / 打码 / 水印**；
- 点分类后，左侧出现该分类的属性面板，同一时刻只显示一个；
- 面板切换带 130ms 淡入，不会「啪」地跳出来；
- 分类轨顶部有 **⟨ / ⟩ 折叠按钮**：一键把属性面板整栏收起，只留分类图标，画布更宽；
- 全部颜色走主题资源，浅色 / 深色模式都正常，不会出现深色下白底黑字的割裂感。

| 分类 | 内容 |
|---|---|
| 基础 | 旋转、水平/垂直翻转、拉直、输出尺寸 |
| 裁剪 | 自由 / 1:1 / 4:3 / 16:9 / 4:5 / 3:4 / 9:16 比例、裁剪框 |
| 调色 | 亮度 / 对比度 / 饱和度滑块、5 款一键滤镜、滤镜强度、我的预设 |
| 文字 | 添加文字、文字水印、字体 / 字号 / 颜色 / 描边、斜放角度 |
| 标注 | 涂鸦、矩形 / 箭头 / 椭圆标注 |
| 打码 | 马赛克 / 高斯模糊画笔、矩形打码、颗粒强度 |
| 水印 | 平铺文字水印、图片水印（PNG），透明度与位置 |

## 2. 基础与裁剪：旋转、拉直、翻转、尺寸

- **固定比例裁剪**：下拉框可选 `自由 / 1:1 正方形 / 4:3 相框 / 3:4 / 16:9 宽屏 / 4:5 / 9:16`。
  选比例后，拖任意一个角或边，裁剪框都按该比例缩放；矩形不需要正方形时会自动吸附到可用范围。
  （4:5 / 3:4 / 9:16 覆盖小红书竖图与手机壁纸。）
- **裁剪框**：8 个白色手柄 + 三分构图线，框内可整块拖动；底部实时显示裁剪后的像素尺寸。
  裁剪完成会按「显示坐标 → 源图坐标」换算，导出时作用在原图真实分辨率上，不是预览小图。
- **拉直（±15°）**：滑块微调水平线，整图旋转后居中裁掉四角空白，预览与导出共用同一套几何系数。
  地平线歪了不用再靠裁剪硬凑；「重置拉直」一键归零。
- **水平 / 垂直翻转**：两个按钮直接生效。
  只镜像画面与标注位置，文字内容本身不镜像（否则会变成反字）；
  垂直翻转在内部按「旋转 180°」处理，后续再旋转不会出现方向错乱。
- **自定义尺寸**：下拉框预设 `保持原始 / 长边 2560 / 1920 / 1280 / 自定义…`。
  选「自定义」后可输入宽高（如 1920 × 1080），保存时按该尺寸输出；
  过大的值会被自动限制（长边 ≤ 20000、总像素 ≤ 4000 万），避免内存打爆。
  面板底部常驻一行「输出：xxx × xxx 像素（可见区域 …）」，随时能看到最终会导出多大。

## 3. 调色：滑块 + 滤镜，带实时预览

- **三个滑块**：亮度、对比度、饱和度，范围 −100 ~ +100，右侧实时显示数值。
- **实时预览**：拖动滑块时画布上的图立刻变化，不用点保存、不用等。
  实现方式不是 ShaderEffect，而是**后台线程用 ImageSharp 处理一份降采样副本**：
  - 几何变换（裁剪/旋转/翻转）只在变化时做一次，结果缓存；
  - 拖滑块时只对这张小图做颜色运算，长边 1400，速度足够跟手；
  - 70ms 防抖 + 世代令牌：连续拖动只渲染最后一帧，过期结果直接丢弃，不会闪回旧颜色；
  - 整个计算在后台线程，UI 线程不阻塞。
- **一键滤镜**：原图 / 黑白 / 暖色 / 复古 / 日系，点一下直接套用，当前滤镜按钮高亮。
- **滤镜强度**：0 ~ 100% 滑块，把滤镜结果与原图线性混合。
  日系 / 复古这类重滤镜觉得「过」时可以直接减半，不必放弃整个滤镜。
- 滤镜与滑块可以叠加（先套滤镜，再微调亮度对比度）。
- 「重置」把三个滑块归零，滤镜保持不变。
- **我的预设**：把当前「调色参数 + 滤镜 + 滤镜强度 + 最后一段文字水印」存成命名预设，
  一键套到其它图片；预设保存在数据目录的 `editor-presets.json`，支持改名覆盖与删除。
  套用时若图里已有同文本的水印，只更新样式，不会重复叠加。

## 4. 文字 / 标注 / 打码（拆成独立分类）

### 4.1 马赛克 / 模糊画笔

- 「马赛克」工具里有两种效果：**马赛克**（像素块）和 **模糊**（高斯模糊），下拉框切换。
- 两种画法：
  - **画笔**：按住拖动涂抹，涂抹轨迹实时变成马赛克 / 模糊；
  - **矩形**：拖出一个矩形，框内区域整块打码。
- 画笔大小可调（8 ~ 160），笔迹是圆头，交叉处会自然合并，不会出现接缝。
- **颗粒强度可调**（4 ~ 40）：马赛克方块大小不再固定为画布宽度 / 60。
  证件号需要细颗粒、人脸需要粗颗粒，可以按场景分别设置；不同颗粒的笔迹会分层渲染。
- 适合遮挡证件号、车牌、聊天截图里的隐私信息。
- 每一步都进撤销栈，画错了 Ctrl+Z 即可。

### 4.2 涂鸦

- 自由画笔，6 个常用颜色 + 粗细滑块。
- 导出的笔迹宽度按图片尺寸等比换算，预览和成品粗细一致。

### 4.3 形状标注：矩形 / 箭头 / 椭圆

- 「局部」里新增三个形状工具，按住在画面上拖动即可绘制：
  - **矩形框**：圈出截图里的某一块重点；
  - **箭头**：从起点指向终点，箭头大小随线宽自动适配；
  - **椭圆**：圈人、圈图标。
- 颜色与线宽复用涂鸦的调色板与粗细设置；预览与导出共用同一套几何绘制代码，位置不会偏。
- 拖动小于 6 像素的误触会被忽略；每次绘制单独进撤销栈。

### 4.4 文字升级

- **字体**：默认（微软雅黑）/ 黑体 / 宋体；
- **字号**：滑块调节，实时生效；
- **加粗 / 斜体**；
- **文字底色**：可选透明或半透明黑底 / 白底，白字压在花背景上也能看清；
- **描边**：可选黑 / 白描边，描边宽度可调（3% ~ 20% 字号），彻底解决「白字看不见」；
- **斜放角度**（−180° ~ +180°）：绕文字中心旋转，任意角度斜放水印；
  滑块固定在「文字」面板顶部、不需要进入编辑就能看到；没有选中文字时作用于最后一段；
- 拖动顶部「✥ 拖动」条移动位置；点画布空白处或按 Esc 结束这段文字；
- 内容清空的文字会被自动丢弃，不会留下看不见却会被导出、还会挡住点击的空文本框。

## 5. 水印

- **平铺水印**：输入一段文字，按固定角度与间距重复铺满整张图，适合版权 / 出处：
  - 文字内容可直接编辑；字号（占画面宽度 1.5% ~ 12%）、斜放角度（−180° ~ 180°）、
    疏密（间距 0.4× ~ 4× 字号）、不透明度（4% ~ 60%）、颜色都可调；
  - 用图案平铺（DrawingBrush）渲染，图案再密也只有 1 个图层，预览和导出都不会拖慢；
  - 同一时间最多一个平铺水印，可整体删除并撤销。
- **文字水印**：一键在右下角放一段默认半透明文字（可再改内容、字号、颜色、透明度、位置）。
- **图片水印**：从本地选择一张 PNG（推荐带透明通道的 Logo），放到画面上：
  - 拖动水印本体移动位置；
  - 拖右下角小白点缩放，**保持原始宽高比**，不会被拉扁；
  - 右侧「不透明度」滑块可调，范围 5% ~ 100%；
  - 右下角「删除水印」可移除当前选中的图片水印。
- 水印坐标同样按归一化存储，裁剪、旋转、翻转后位置与比例会跟着换算。
- 旋转 90° 后画布宽高互换，笔迹 / 形状线宽、马赛克颗粒、平铺水印字号都会按新旧宽度换算，
  横图转竖图不会被悄悄放大或缩小。

## 6. 撤销 / 重做覆盖所有操作

- 支持：旋转、翻转、裁剪、拉直、滤镜、滤镜强度、亮度/对比度/饱和度、输出尺寸、预设套用、
  文字（新增/编辑/删除/角度）、涂鸦、形状标注、马赛克/模糊（含颗粒）、
  平铺水印（新增/文字/字号/角度/间距/透明度/颜色/删除）、图片水印（新增/移动/缩放/透明度/删除）。
- `Ctrl+Z` 撤销、`Ctrl+Y` 重做；按钮悬停会显示即将撤销/重做的操作名。
- 一次滑块拖动只记**一条**撤销记录（松手或停手 0.8 秒后合并），不会出现「拖一下要按 30 次撤销」。
- 文字编辑以「会话」为单位：同一段文字的连续修改合并为一次撤销。

## 7. 保存：依然只存副本，且按原图尺寸渲染

| 打开的文件 | 保存行为 | 按钮 |
|---|---|---|
| 原图 `cat.jpg` | 新建 `cat_edited.jpg`，原图一个字节都不动 | 💾 保存副本 |
| 副本 `cat_edited.jpg` | 原地覆盖这个副本 | 💾 更新副本 |

- 最终渲染用 **ImageSharp 从原图重新解码**，按裁剪 → 旋转 → 翻转 → 目标尺寸 → 调色的顺序烘焙，
  因此输出的是**原图分辨率的成品**，不受查看器「4096 像素解码上限」影响，也不会因为预览是 1400 而变糊。
- 文字、涂鸦、打码、图片水印在烘焙结果上用 WPF 合成，与预览共用同一套绘制代码，保证「所见即所得」。
- 写盘仍是「同目录临时文件 + 原子替换」：中途失败原文件不受影响。
- 提示条会明确写「原图未修改」还是「原文件已被覆盖」，并显示输出尺寸与文件大小，可一键打开所在文件夹。

### 7.1 复制到剪贴板

- 顶栏新增「📋 复制」：按原图分辨率渲染当前效果后放进系统剪贴板，
  编辑完直接 `Ctrl+V` 粘到微信 / QQ，不用先落盘再发送。
- 剪贴板被其它程序短暂占用时会自动重试一次；失败会明确提示，不会悄悄吞掉操作。

### 7.2 另存为…

- 顶栏新增「另存为…」：自选**保存位置、格式（PNG / JPEG / WebP / BMP）与 JPEG / WebP 质量**。
- 切换格式时自动同步扩展名；目标文件已存在会先确认覆盖；
- 仍然遵守「不毁原图」：目标路径等于正在编辑的源文件时直接拒绝；
- 渲染与写盘复用保存副本的同一套原子写盘流程，中途失败不会留下半张图。

## 8. 性能与稳定性

- 调色预览全程在后台线程，UI 不卡；快速翻页时旧任务的结果会被令牌丢弃，不会覆盖新图。
- 几何预览缓存按「文件路径 + 长度 + 修改时间 + 裁剪 + 旋转 + 翻转」做键，同一张图连续调色不重复解码。
- 所有叠加层坐标统一钳制到 0~1，避免异常值把元素画到画布外、在导出图上留下黑边或白块。
- 切换图片、关闭窗口会解绑事件并释放预览缓存，避免位图被长期引用。

## 9. 已知限制（有意为之，不是漏做）

1. **调色预览是降采样版本**（长边 1400），保存时才是全分辨率。
   这是为了小内存 / 弱显卡机器也能跟手拖动；成品清晰度不受影响。
2. **自定义尺寸按等比适配**：输入的宽高作为一个框，可见区域等比缩进框内，不拉伸变形；
   想得到精确的 1920×1080，先把裁剪比例设为 16:9 再填自定义尺寸（面板会实时显示实际输出尺寸）。
3. **副本不携带任何 EXIF 元数据**（有意为之，不是漏做）：拍摄时间、机型、GPS 一概不搬。
   编辑副本大概率会被分享出去，GPS / 设备序列号属于隐私元数据，扩散后收不回来。
   像素已在烘焙时按 EXIF 方向转正，所以也不需要写 Orientation 标记（缺省即 1，所有解码器都按正立处理）。
   产品里没有依赖「拍摄时间」的字段（`MediaItem` 只有文件系统时间），因此不搬元数据不丢任何功能。
4. **矩形打码内部按轨迹填充**实现（复用同一套渲染），边缘是圆头笔迹的合并结果，不是硬边矩形；
   需要硬边时建议用「马赛克」效果 + 贴近边缘的矩形拖动。
5. **图片水印不支持旋转角度**，只支持移动、等比缩放、透明度（文字与水印文字已支持 −180° ~ +180° 旋转）。
6. **文字描边在编辑状态下不显示**（TextBox 无法描边），结束编辑后立刻按描边渲染。
7. 裁剪预览是 WPF 侧显示效果，最终裁剪在原图上按归一化矩形换算，可能出现 1 像素级取整差异。
8. **预设只保存「调色 + 最后一段文字水印」**：裁剪、形状、涂鸦属于单图内容，不随预设复用；
   想给多张图套同一套裁剪，请用固定比例裁剪分别处理。
9. **预设不跨设备同步**：保存在本机数据目录的 `editor-presets.json`，可用便携模式随程序目录搬走。

## 11. 全局快捷键（设置 → 快捷键）

设置窗口新增「⌨ 快捷键」分类，四项都能自定义，默认只有第一项带组合：

| 动作 | 行为 | 默认 |
|---|---|---|
| 显示 / 隐藏主窗口 | 任何时候按一下把窗口叫到前台；已经在前台时再按一下收进托盘 | `Ctrl+Alt+Shift+M` |
| 打开「发现」页 | 直接跳到随机推送那批素材 | 未设置 |
| 随机看一张（当前视图） | 在当前列表里随机打开一张，连续按不会连着同一张 | 未设置 |
| 打开设置 | 不用先回主界面 | 未设置 |

- **录键**：点右边的按键框 → 直接按下组合键；`Esc` 取消，`Delete` 清除。
  可以单独用 `F1`~`F24`，其它键必须带 `Ctrl / Alt / Shift / Win`（单按字母会劫持系统输入，直接拒绝）。
  一个组合只能给一个动作用，重复时自动从原来的动作上移走并提示。
- **不静默失败**：被别的程序占用时，保存后会逐条列出「哪个动作 + 什么组合 + 为什么」；
  启动时注册失败则在主界面状态栏提示，并指路到设置页。
- **保存即生效**，不用重启。录键期间会临时注销全部热键，避免按到自己的组合把窗口弄没。
- **为什么默认是三键**：实测 `Ctrl+Alt+M`、`Ctrl+Alt+F` 在装了开发工具 / 截图工具的机器上常已被占用，
  `Ctrl+Alt+Shift+M` 基本不会撞。
- **实现**：独立消息窗口（`HwndSource`）接收 `WM_HOTKEY`，不挂在主窗口上（主窗口隐藏/重建都不影响注册）；
  `MOD_NOREPEAT` 防按住连发；退出时统一注销，换版本重开不会残留占用。
- 顺手修掉设置窗口的老问题：内容区原先允许横向滚动，导致长说明文字不换行、右侧被切掉；现在只允许纵向滚动。

## 13. 查看器：沉浸式随机跳转

查看器顶部新增 **🎲 随机跳转**（快捷键 `R`）与旁边的 **▾** 范围菜单：

- **原地切换**：不销毁窗口、不重建窗口，只替换查看器的数据源；切换前 70ms 淡出、切换后 80ms 淡入，
  共 0.15 秒，给一个「闪一下」的反馈。
- **随机范围**（记住选择，存在 `ViewerRandomScope` 设置里）：
  当前列表结果 / 当前文件夹（这张图所在根目录）/ 全部媒体库 / 仅收藏 /
  指定分类、收藏夹或标签（菜单里直接选）。
- **不会连续抽到同一张**：选取前按 Id + 路径排除当前项；范围内只有 1 张时提示
  「当前范围内的媒体太少啦，无法随机」。
- **上下文跟着范围走**：当前列表范围直接复用内存列表；其他范围查库后把查看器列表替换成该范围的图片，
  上一张/下一张与撤销栈都切到新图所在上下文。
- **不抢输入**：焦点在文字编辑框、备注等输入控件时，`R` 仍然是输入字母；`Ctrl / Alt / Shift + R` 不触发。
- **内容限制**：查看器只负责图片，随机结果固定为图片；视频继续用独立播放器（按「仅视频」会破坏原地切换，
  所以没有做进查看器）。
- 标题栏与底部状态栏文件名同步更新；跳转前若有未保存的编辑会先确认，不会静默丢弃。

## 14. 验收中修掉的两个问题（v1.3.0 发布前）

这两条都是端到端验收（`build/acceptance.py`）跑出来的，靠单元测试抓不到，靠肉眼点几下也容易漏：

### 14.1 新用户打开「发现」页是空白的

- **现象**：干净数据目录 + 刚扫描完 53 个文件 → 点「✨ 发现」→ 一屏 0 项，状态栏「发现 · 0 项随机推荐」。
  明明库里有东西，看起来却像坏了。
- **根因**：默认推荐池是「收藏」，新用户一张都没收藏，池子为空 → 随机取数返回 0 条；
  欢迎引导只在「整库为空」时出现，所以什么都不显示。
- **修法**：池子为空且不是「全部」时，本批**自动回退到全库**，并在状态栏说明
  「（收藏还是空的，这次先看全库）」。用户的推荐池设置不动，收藏过之后自然恢复成「只看收藏」。
- **为什么重要**：发现页是新版的主打功能，第一眼空白等于这个功能不存在。

### 14.2 中文输入法把单键快捷键全吃掉

- **现象**：输入法在中文状态时，按 `R`（换一批）、`F`（收藏）、`1`~`5`（打星）都没反应，
  反而弹出输入法候选框（候选词是「让 / 如 / 日 / 若 / 任 / 热」）。
- **根因**：`R` / `F` / 数字都是字符键，中文输入法会先拦截做拼音组合，WPF 层收不到 `Key.R`
  （只有 `Key.ImeProcessed`），**而且窗口开着输入法时，录屏里也会出现候选框**。
- **修法**：主窗口 `InputMethod.IsInputMethodEnabled="False"`，只给「搜索框」和「备注框」
  单独打开输入法（`="True"`）；同时 `OnKeyDown` 里把 `Key.ImeProcessed` 归一成 `ImeProcessedKey`，
  并加一条「焦点在 TextBox 里时单键快捷键不生效」的保护（避免在搜索框打字误触发收藏）。
- **验证**：修完后同一条验收脚本，`R 换一批` 从 FAIL 变 OK，且截图里不再出现输入法候选框。

> 这两条也说明一件事：**单元测试只能证明算法对，端到端才能证明"用户点得到"**。

## 15. 发布前一晚的三处修复 + 时光机（v1.3.0 定稿）

手感反馈阶段抓出来的三条，以及一个被用户点名的数据安全需求。

### 15.1 框选时滚轮失效，选不了视图外的图片

- **现象**：按住左键在网格空白处拖出选框，想继续往下选，滚轮完全没反应，
  只能先松手滚一格再重新框；截图里那条蓝框就是这个状态。
- **根因**：框选期间 `ThumbList` 上挂着 `CaptureMouse()`，WPF 会把滚轮事件从**捕获元素**往上冒泡到 `Window`；
  而 `ScrollViewer` 是 ListBox 模板里的**子元素**，永远收不到这个事件 —— 于是"滚轮没反应"。
  正常状态（没有捕获时）滚轮是好的，所以单测和上一轮验收都没抓到。
- **修法**：`ThumbList` 上挂 `PreviewMouseWheel`，**只在框选中**接管：把滚轮事件重新抛给
  ScrollViewer 自己处理（`sv.RaiseEvent(new MouseWheelEventArgs(...))`），框架逻辑比手算偏移可靠。
- **另一条**：拖到网格上/下边缘 26px 内会启动 60ms 定时器自动滚动，
  一边拖一边选，一屏之外的内容也能框进来（结束后 `EndMarquee` 一定停表）。
- ⚠ **踩坑**：一开始用 `sv.LineDown()` 自己做滚动，结果**滚轮彻底失灵**。
  `VirtualizingWrapPanel` 的偏移单位不是像素，`LineDown()` 实测是空操作；
  必须"借道" ScrollViewer 的默认处理。

### 15.2 中文输入法仍然吃掉单键快捷键（二次加固）

- 之前只做了 `InputMethod.IsInputMethodEnabled="False"` + `Key.ImeProcessed → ImeProcessedKey` 归一，
  实测对部分中文输入法不够：`R`（换一批）还是会被输入法先拿去组拼音。
- 新增 `Services/InputMethodGuard.cs`：在 Win32 层把窗口的 IME 上下文摘掉
  （`ImmAssociateContext(hwnd, IntPtr.Zero)`），按键就原样以 `Key.R` 进来；
  焦点进入 `TextBoxBase`（搜索框 / 备注框）时把上下文挂回去，离开立刻再摘掉。
- `ImmAssociateContext` 返回 0 的输入法（本来就没上下文）用 `ImmCreateContext()` 补一个再挂回去，
  否则输入框里会打不出中文。
- 原有两条兜底逻辑保留：`ImeProcessedKey` 归一、焦点在 TextBox 里时不触发单键快捷键。

### 15.3 托盘右键菜单不跟主题

- **现象**：深色主题下，托盘右键菜单仍是白底黑字，和主界面完全割裂。
- **根因**：托盘是 WinForms 的 `ContextMenuStrip`，**不吃 WPF 资源字典**；
  只改 `BackColor` 还会残留系统渐变块。
- **修法**：整套自绘 `ToolStripRenderer`（背景 / 悬停 / 分隔线 / 禁用项颜色），
  配色直接从当前主题资源里取（`PanelColor` / `TextColor` / `HoverColor` / `BorderColor`），
  主题切换时 `App.ApplyThemeNow` 会回调 `TrayIconService.ApplyTheme()` 重新上色。
- ⚠ **踩坑**：给 `ContextMenuStrip` 写 `RenderMode = ToolStripRenderMode.Custom` 会**直接抛异常**
  （"RenderMode 属性不能直接设置为 Custom；若要使用自定义的 ToolStripRenderer，应设置 Renderer 属性"），
  异常发生在启动引导里 → 整个数据加载被跳过，界面空白只剩侧栏。
  正确姿势：只赋 `Renderer`，`RenderMode` 会自动变成 Custom。

### 15.4 🕒 历史快照（时光机）：一键退回某个自动备份节点

设置 → 备份与迁移 里新增一块「历史快照（时光机）」：

- 列出 `library.db.bak.1 ~ .7`（跟随「备份目录」设置，可指向 U 盘），
  **按时间从新到旧**排列，每行显示 `2026-10-22 14:30:00`、相对时间（3 小时前）、文件名与大小，
  最新一份带「最近一次」徽标；每行右侧是 **🔄 恢复至此节点**。
- 恢复前的二次确认写明：覆盖当前数据、恢复到哪个时刻、恢复前会自动保存当前状态。
- 另有 **📦 立即备份一次**（刚整理完就钉一个时间点，不用等间隔）。

**恢复流程（顺序不能改，改之前请先读代码注释）**：

1. 遮罩层锁界面：「正在恢复数据，请勿关闭软件…」，全程不会被误点；
2. **先校验节点**：`PRAGMA quick_check`，坏文件一律拒绝，绝不拿坏备份覆盖好库；
3. 停掉后台工作：取消扫描、缩略图队列、定时备份循环、尺寸补齐；
4. 对当前库 `wal_checkpoint(TRUNCATE)`，让 -wal 落盘（否则安全副本是旧的）；
5. `SqliteConnection.ClearAllPools()` 安全断开所有连接；
6. 复制当前库 → `library.before_restore.db`（后悔药）；
7. **先删 `-wal` / `-shm` / `-journal`，再 `File.Copy` 覆盖** ——
   顺序反了会把旧 WAL 的帧套到新库上，这是最容易被忽略的损坏来源；
8. 覆盖后重新 `quick_check` 校验；不合格立刻用安全副本回滚；
9. 成功后 `Process.Start` 重启自己再退出（**故意不重建 DataContext**：那条路太容易留下悬挂连接）；
10. 失败提示「恢复失败，原文件未损坏，请重试」，并给出安全副本路径。

**顺手修掉的一个坑**：`OnExit` 里原本会无条件备份一次。
恢复完成后重启时，这次退出备份会立刻把 `bak.1..7` 整体轮换一遍 ——
用户刚看到的「时间节点」全被挪位，刚恢复的那个节点还可能被覆盖。
现在恢复流程会置位 `_suppressExitBackup` 跳过它。

**测试**（`tests/MediaManager.Tests/DatabaseSnapshotTests.cs`，8 条）：
时间倒序、空目录、坏文件被拒、缺失文件被拒、恢复后数据真的回到那一刻、
安全副本里是"恢复前"的数据、覆盖后不残留 -wal/-shm、坏节点不触碰现有数据、
安全副本回滚可用、展示字段格式。
