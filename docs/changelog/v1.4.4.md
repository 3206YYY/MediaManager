# v1.4.4 — 插件不再「永远弹同一个错误框」

## 这一版做了什么

v1.4.3 发完之后没有动任何界面功能，这一版只做一件事加几个小修：

1. **插件熔断**：一个每次都出错的插件动作，以前用户每点一次就弹一次同样的错误框，
   永远弹下去；现在同一插件的动作**累计出错 3 次就整组自动停用**，
   状态栏提示「插件 ×××已停用（连续出错）」，🧩 插件菜单入口自动收起。
   设置页里的插件状态从此是三态：绿「已加载」/ 橙「已停用（连续出错）」/ 红「加载失败」。
2. **独立打开文件的类型分流收敛到唯一判断点**：资源管理器右键打开、拖文件进窗口、
   命令行传文件，以前各有一份「图片视频内置、其它交给系统」的判断，
   现在统一走 `MediaOpenStrategy`——行为完全没变，防的是将来改一处漏一处。
3. **托盘图标句柄修复**：退出时托盘图标的 GDI 句柄以前不会被释放；顺带修掉了
   回退路径可能把系统共享图标释放掉的问题（极端情况下会伤到别的程序图标）。
4. **读屏友好**：缩略图网格的文件项以前向读屏软件报告的是类名
   （`ThumbnailItemViewModel`），现在报告文件名。

## 质量账本

- 单元测试 **281 → 347**（Core/Infrastructure 275 + App 层 72）。
  App 层这次补上了文件类型图标映射、缩略图内存缓存行为（并发共享解码、
  「滚动划走零成本丢弃」、预算下限）、拖拽判定、快捷键清单一致性。
- 新增两个可以自己复跑的实机脚本：
  - `build/verify/verify_video_player.py`——视频播放器 10 项断言
    （窗口、无错误面板、时长加载、播放中时间推进、空格暂停、暂停步进、恢复），
    以前视频播放器是实机覆盖的空白；
  - `build/verify/verify_memory.py`——内存实测（空载约 218 MB，
    打开查看器约 303 MB，关闭后 301 MB，Debug、27 条开发库，只记数字不下结论）。
- 全量编译 0 警告 0 错误。

## 升级说明

从 v1.4.x 直接覆盖安装即可，数据不动。没有设置项变化，没有格式变化。
