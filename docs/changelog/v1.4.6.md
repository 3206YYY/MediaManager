# v1.4.6 — 启动时悄悄看一眼有没有新版，只提示、不下载

这一版只做一件事：让程序自己知道「外面有没有新版」，并且只提示、绝不动手。

以前想看有没有更新，得自己点开 GitHub 翻 Release；现在启动几秒后会在后台问一次，
有新版就弹一个窗：改了什么、多大、去哪下。没有任何后台下载、没有静默安装、没有偷偷重启，
装不装、什么时候装都由你决定。不想被打扰可以点「跳过这个版本」，同一个版本以后不再问。

## 这个版本加了什么

- 启动时自动检查新版本（默认开，可在设置里关掉）。
- 更新提示会列出这版改了什么，不再只丢一句「有新版本」。
- 「跳过这个版本」记住你的选择，同一版本不再打扰。
- 设置 → 关于与更新 加了开关，并写明本软件不会后台下载安装。
- 手动「检查更新」也走同一个窗口，说法一致。

## 更新提示长什么样

窗口里只有四样东西：

1. 当前版本 → 新版本（一眼看出差多少）
2. 发布时间和安装包体积（决定「现在换不换」）
3. 改了什么：一句概括 + 最多 5 条要点，其余点「查看完整说明」去发布页
4. 三个选择：去下载 / 跳过这个版本 / 以后再说

刻意不做「一键更新」。自动替换正在运行的程序文件，在任何软件里都是最容易出事的一步
（文件占用、杀软拦截、更新到一半断电）。这一版先把「知道有新版」这件事做扎实。

## 顺手做的一件内部事

`MainViewModel` 原来是 2774 行一个文件、207 个成员，改任何一处都要在这一大坨里找，
「改 A 碰到 B」是常态。现在按职责拆成 7 个文件：

| 文件 | 行数 | 管什么 |
|---|---|---|
| MainViewModel.cs | 365 | 字段、构造、初始化、状态 |
| MainViewModel.Browsing.cs | 451 | 导航、文件夹树、视图切换、搜索 |
| MainViewModel.Media.cs | 614 | 列表加载、缩略图、详情 |
| MainViewModel.Discovery.cs | 234 | 发现页与筛选 |
| MainViewModel.Scanning.cs | 437 | 根目录、扫描、文件监视 |
| MainViewModel.Delete.cs | 320 | 删除、批量删除、撤销 |
| MainViewModel.Organize.cs | 500 | 重命名导出、标签分类、排序 |

纯搬移，一行逻辑没改（编译 0 警告，367 项测试全过）。另加 `verify_code_health.py`
守着它别再长回一个巨型文件。

## 验证

- 单元测试 367 → **413 项**（新增 46 项，集中在「该不该提示」「说明怎么截」这类判断上——
  这些判断错了的后果是两个极端：该提示的不提示，用户永远停在旧版；不该提示的天天提示，
  用户直接关掉开关，等于永久失去更新通道）。
- 新增两个实机脚本：`verify_update_prompt.py`（21 项）、`verify_update_settings.py`（7 项），
  覆盖弹窗内容、跳过生效、关掉开关后完全不发请求。
- 回归：批量删除 67/67、嵌套文件夹 11/11、开源许可 18/18、代码健康 25/25。

## 安装

下载 `MediaManager-Setup-1.4.6.exe` 覆盖安装即可，库、分类、标签、私密空间都会保留。
