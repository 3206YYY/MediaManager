# v1.4.0 L1 设计文档：扩展格式支持（音频 / 文档 / 压缩包）

> **状态**：草案（待评审）
> **目标版本**：v1.4.0
> **范围**：L1「只读浏览」三类 + 安装包可选组件
> **基线**：v1.3.0（当前代码）
> **关联文档**：`docs/plugin-api.md`（现有菜单动作插件，与本方案是两套不同机制）

---

## 1. 背景与目标

当前软件只管理**图片 / 视频**。用户希望把常见的 **音频（mp3 等）、文档（txt/md/json 等）、压缩包（zip/rar/7z 等）** 也纳入同一个库，从"媒体管理器"升级为"本地文件管理器"。

本阶段（L1）只做**只读浏览**，验证"多类型进库 + 统一浏览"这条链路是否可行，不在这一版做编辑/转换/解压。

### 1.1 一句话目标

> 用户添加一个混放 mp3、txt、zip 的文件夹后，这些文件能和图片/视频一起被扫描、筛选、双击查看，且不影响原有图片/视频体验。

### 1.2 为什么不是「用现有插件实现」

现有插件契约（`MediaManager.Core.Plugins.PluginContracts.cs`）**只提供菜单动作**：插件拿到"当前选中的路径"，注册一个右键/工具栏菜单项，**碰不到扫描、数据库、缩略图、查看器**。

而"支持一种新文件类型"必须贯穿：扫描识别 → 入库 → 缩略图分派 → 列表呈现 → 双击打开 → 筛选。因此这是**核心管线扩展**，不是菜单插件。两者定位不同，不要混用。

## 2. 范围（L1 MVP）

### 2.1 本版要做

| 能力 | 说明 |
|------|------|
| 识别 | 新扩展名能被扫描器识别为 `Audio / Text / Archive` |
| 入库 | 写入现有 `MediaItem` 表（复用全部现有分类/标签/收藏/搜索能力） |
| 列表 | 缩略图网格里用**类型图标**呈现；有封面的音频可显示封面 |
| 打开 | 音频→内置播放器；文档→只读预览；压缩包→条目列表 + 用系统程序打开 |
| 筛选 | 顶部可按类型筛选（全部/图片/视频/音频/文档/压缩包） |
| 详情 | 详情面板显示对应信息（时长 / 大小 / 条目数） |
| 可选安装 | 安装包勾选"扩展格式支持"才拷贝扩展程序集；不勾选则三类不被扫描 |

### 2.2 明确不做（留到 L2 / L3）

- 文本/文档的**渲染预览缩略图**（L1 只用图标；渲染成本高，容易卡）。
- 压缩包的**解压 / 压缩 / 预览内部文件**（L1 只列条目）。
- 音频 ID3 **标签编辑**、歌词、频谱。
- 任意类型之间的**格式转换**、批量处理。
- 第三方类型插件的**动态加载市场**（本版只给内置三类留好契约）。
- 把「发现页」扩展到非视觉类型（发现页保持图片/视频）。

## 3. 现状与扩展点（基于 v1.3.0 代码核对）

| 位置 | 现状 | 对本方案的影响 |
|------|------|------|
| `MediaItem.MediaType` | `TEXT NOT NULL`，**无 CHECK 约束**；启动时把历史 `"0"/"1"` 归一为 `"Image"/"Video"` | 新增类型是**加法**，旧数据无需迁移 |
| `MediaType` 枚举 | `Image = 0, Video = 1` | 追加 `Audio = 2, Text = 3, Archive = 4` |
| `MediaFormat` | 硬编码 `Images` / `Videos` 两个集合；`GetMediaType` 返回 `MediaType?` | 重构为**类型目录**，支持注册 |
| `ScanService` | 统一走 `MediaFormat.GetMediaType(file)`；`null` 跳过；仅 `Image` 补宽高 | **几乎不用改**；新类型自动入库 |
| `ThumbnailService` | `MediaType.Image ? ImageSharp : FFmpeg` | 需加分支：Audio/Text/Archive 先走图标 |
| `ThumbnailItemViewModel` | `IsVideo` | 需加 `MediaKind` / `TypeGlyph` / `IsVisual` |
| `MainWindow.OpenViewer` | 视频→`VideoPlayerWindow`，否则→`ViewerWindow` | 需按四类路由 |
| `OpenStandaloneFile`（P2-8） | 同上 | 同样按四类路由 |
| `MainViewModel.BuildFilter` | 仅图片/仅视频两个开关 | 升级为类型筛选 |
| `MediaFilter.MediaType` | 单值 `MediaType?` | 单值足够（配"全部"选项）；如需多选再加列表 |
| 发现页查询 | 按池子取随机项 | 需**限定 Image/Video**，避免稀释 |
| `DeletedItem` | `MediaType` 默认 `'Image'` | 需审删除/还原逻辑是否只认图片/视频 |

> 全仓 `IsVideo / MediaType.Image / MediaType.Video` 直接判断约 **27 处**（`grep` 实测），施工时逐个审。

## 4. 架构设计

### 4.1 总体思路

1. **类型目录（Catalog）**：把"扩展名 → 类型"从硬编码改为可注册。
2. **类型提供者（Provider）契约**：每个类型由一个 provider 描述（扩展名、显示名、图标、能力）。
3. **扩展程序集**：音频/文档/压缩包三个 provider 编译进独立 dll，放 `{app}\Extensions\`。
4. **加载器**：主程序启动时扫描 `Extensions\`，把 provider 注册进 Catalog；dll 不存在 = 三类不参与扫描。
5. **查看器路由**：App 层按 `MediaType` 分派到四个窗口（图片/视频/音频/文档/压缩包）。

### 4.2 `IMediaTypeProvider` 契约

```csharp
namespace MediaManager.Core.Media;

/// <summary>一个文件类型提供者：认领若干扩展名，并声明其基础能力。</summary>
public interface IMediaTypeProvider
{
    /// <summary>稳定标识，例如 "audio" / "text" / "archive"。</summary>
    string Id { get; }

    /// <summary>归入的媒体大类（写入 MediaItem.MediaType）。</summary>
    MediaType MediaType { get; }

    /// <summary>认领的扩展名（小写、带点，例如 ".mp3"）。</summary>
    IReadOnlyCollection<string> Extensions { get; }

    /// <summary>显示名（筛选、详情用）。</summary>
    string DisplayName { get; }

    /// <summary>列表占位图标（emoji 或字符）。</summary>
    string Glyph { get; }

    /// <summary>是否支持“在应用内打开”。</summary>
    bool CanOpenInApp { get; }
}
```

> L1 的 provider **只做描述**。缩略图生成、查看器创建仍在 App 层按 `MediaType` 分派。
> Phase 2 再给契约追加 `GenerateThumbnailAsync` / `CreateViewer`，让第三方 provider 自带实现。

### 4.3 `MediaFormat` 重构为类型目录

```csharp
public static class MediaFormat
{
    private static readonly Dictionary<string, MediaType> _byExt =
        new(StringComparer.OrdinalIgnoreCase);

    private static readonly Dictionary<MediaType, IMediaTypeProvider> _providers = new();

    static MediaFormat()
    {
        // 内置图片/视频（保证扩展程序集缺失时基础功能不受影响）
        RegisterBuiltin(new ImageMediaTypeProvider());
        RegisterBuiltin(new VideoMediaTypeProvider());
    }

    public static void Register(IMediaTypeProvider provider)
    {
        _providers[provider.MediaType] = provider;
        foreach (var ext in provider.Extensions)
            _byExt[ext] = provider.MediaType;
    }

    public static MediaType? GetMediaType(string path)
        => _byExt.TryGetValue(Path.GetExtension(path), out var t) ? t : null;

    public static bool IsImage(string path) => GetMediaType(path) == MediaType.Image;
    public static bool IsVideo(string path) => GetMediaType(path) == MediaType.Video;
    public static bool IsSupported(string path) => GetMediaType(path) != null;

    public static IReadOnlyCollection<MediaType> SupportedTypes => _providers.Keys;
    public static IMediaTypeProvider? GetProvider(MediaType type)
        => _providers.TryGetValue(type, out var p) ? p : null;
}
```

关键点：
- **静态构造时内置图片/视频**，保证不装扩展也有基础功能。
- `GetMediaType` 只查字典，扫描热路径开销可忽略。
- 扫描器、`OpenStandaloneFile` 等现有调用点**无需改动**。

### 4.4 扩展程序集与加载器

```
{app}\
├─ MediaManager.App.exe
├─ MediaManager.Core.dll
├─ Extensions\
│   └─ MediaManager.Extensions.MediaTypes.dll   ← 安装包可选组件
└─ ...
```

加载器（App 层，启动早期调用，必须在任何扫描之前）：

```csharp
public static class MediaTypeExtensionLoader
{
    public static int LoadFrom(string directory)
    {
        if (!Directory.Exists(directory)) return 0;
        var count = 0;
        foreach (var dll in Directory.EnumerateFiles(directory, "*.dll"))
        {
            try
            {
                var asm = Assembly.LoadFrom(dll);
                foreach (var t in asm.GetTypes()
                             .Where(t => typeof(IMediaTypeProvider).IsAssignableFrom(t)
                                         && !t.IsAbstract && !t.IsInterface))
                {
                    if (Activator.CreateInstance(t) is IMediaTypeProvider p)
                    {
                        MediaFormat.Register(p);
                        count++;
                    }
                }
            }
            catch (Exception ex)
            {
                // 单个扩展坏了只跳过，不能拖垮启动
                Log.Warning(ex, "扩展加载失败：{Dll}", dll);
            }
        }
        return count;
    }
}
```

> **程序集解析**：复用现有 `PluginService` 的策略——`MediaManager.*` 一律共享主程序已加载的版本，其余依赖从扩展目录解析，避免同一契约出现两份类型。

### 4.5 查看器路由

新增统一路由（App 层）：

```csharp
private void OpenItem(ThumbnailItemViewModel item)
{
    switch (item.Media.MediaType)
    {
        case MediaType.Video:
            new VideoPlayerWindow { Owner = this }.PlayAndShow(item.Path, this);
            break;
        case MediaType.Audio:
            new AudioPlayerWindow { Owner = this }.Play(item.Path);
            break;
        case MediaType.Text:
            new TextPreviewWindow { Owner = this }.Load(item.Path);
            break;
        case MediaType.Archive:
            new ArchiveInfoWindow { Owner = this }.Load(item.Path);
            break;
        default:
            OpenImageViewer(item);   // 现有逻辑
            break;
    }
}
```

`OpenViewer`（列表双击）与 `OpenStandaloneFile`（拖拽/打开文件）都改为调用 `OpenItem`，保证两条入口行为一致。

## 5. 数据模型与 DB

### 5.1 枚举扩展

```csharp
public enum MediaType
{
    Image = 0,
    Video = 1,
    Audio = 2,
    Text = 3,
    Archive = 4,
}
```

- `MediaItem.MediaType` 是 `TEXT`，写入用 `type.ToString()`（沿用现有约定，**不能传枚举对象**，否则 Dapper 会写成数字）。
- 旧库只有 `"Image"` / `"Video"`，**不需要迁移**；启动时那条 `UPDATE ... '0'→'Image'` 保持不动。
- `DeletedItem.MediaType` 默认值 `'Image'` 无需改，但还原逻辑要审（见 §9.2）。

### 5.2 是否需要新列？

L1 **不需要**。音频时长、压缩包条目数等都可以：
- 实时读取（打开时读，不落库）；或
- 复用现有 `DurationMs` 列（音频时长，扫描时用 MetadataExtractor 读一次）。

推荐：**音频时长写进 `DurationMs`**（成本低、列表/详情都能用）；文本行数、压缩包条目数**不落库**，打开时现算。

## 6. 三类详细设计

### 6.1 音频（Audio）

| 项 | L1 方案 |
|----|------|
| 扩展名 | `.mp3 .wav .flac .m4a .aac .ogg .opus .wma` |
| 缩略图 | 优先读内嵌封面（MetadataExtractor）；没有封面则用类型图标 |
| 时长 | 扫描时用 MetadataExtractor 读，写入 `DurationMs` |
| 打开 | 新建 `AudioPlayerWindow`，复用 LibVLC（不创建 `VideoView`，避免黑边） |
| 控制 | 播放/暂停、进度条、音量、倍速（复用现有播放器防抖经验） |
| 详情 | 时长、格式、码率（可选） |

> 复用点：`VideoPlayerWindow` 的 Seek 防抖、倍速防抖逻辑可直接搬（独立成 `LibVlcPlaybackController` 更好，但不是本版必须）。

### 6.2 文档（Text）

| 项 | L1 方案 |
|----|------|
| 扩展名 | `.txt .md .log .json .csv .xml .ini .yaml .yml` |
| 缩略图 | 类型图标（不做渲染预览） |
| 打开 | `TextPreviewWindow`：只读、等宽字体、带行号（可选） |
| 编码 | 先看 BOM；无 BOM 时按 UTF-8 严格解码，失败回退 GBK |
| 大文件 | 超过阈值（建议 2 MB）只读前 N KB，并提示"文件较大，仅预览前 N KB" |
| 详情 | 文件大小、行数（现算，不落库） |

> 编码探测要注意：中文环境的 `.txt` 很多是 GBK。建议 `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` 后使用 `Encoding.GetEncoding(936)`。

### 6.3 压缩包（Archive）

| 项 | L1 方案 |
|----|------|
| 扩展名 | `.zip .rar .7z .tar .gz` |
| 缩略图 | 类型图标 |
| 打开 | `ArchiveInfoWindow`：条目列表（文件名 / 原始大小 / 压缩后大小） |
| 实现 | zip / tar / gz 用 .NET 内置；rar / 7z 用 `SharpCompress`（MIT） |
| 操作 | 「用系统默认程序打开」；**不自动解压** |
| 安全 | 限制读取条目数/总大小，防 zip 炸弹；只读，不写盘 |
| 详情 | 条目数、压缩后大小、格式 |

> 依赖：`SharpCompress` 为新增 NuGet 包（注意锁版本，和现有"版本固定"约定一致）。若只做 zip，可完全零新增依赖；rar/7z 才需要它。

## 7. UI 设计

### 7.1 顶部类型筛选

现有顶部是「仅图片 / 仅视频 / 已编辑」三个 Toggle。类型变多后建议改为：

```
[类型: 全部 ▾]  [☑ 已编辑]  [缩略图大小 ——]
```

- `ComboBox` 项：全部 / 图片 / 视频 / 音频 / 文档 / 压缩包。
- 保留「已编辑」开关（它是属性，不是类型）。
- 若舍不得点击式，可保留「图片 / 视频」两个快捷 Toggle + 一个「更多类型 ▾」菜单；但 ComboBox 更省空间、更好扩展。

### 7.2 缩略图列表项

- 视觉类型（图片/视频）：沿用现有图片缩略图。
- 非视觉类型：显示大号 `Glyph`（🎵 / 📄 / 🗜️）+ 类型文字，背景用 `PanelBrush`。
- 音频若有封面：按图片方式显示封面，角标显示 🎵。
- 视频的 `▶` 角标逻辑不变。

### 7.3 详情面板

| 类型 | 显示 |
|------|------|
| 图片 | 分辨率、大小、EXIF（现状） |
| 视频 | 时长、分辨率、大小 |
| 音频 | 时长、格式、大小 |
| 文档 | 大小、行数（可选） |
| 压缩包 | 条目数、压缩后大小、格式 |

### 7.4 发现页

**保持只推图片/视频**。在发现页查询（`QueryDiscoveryAsync` / 批次生成）加类型过滤：

```sql
AND MediaType IN ('Image', 'Video')
```

否则用户加了整个盘后，发现页可能推出一堆 txt/zip，体验会崩。

## 8. 安装包可选组件（Inno Setup）

现有 `build/installer.iss` 已有 `[Tasks]`（桌面快捷方式）。新增一个**可选组件**：

```ini
[Components]
Name: "exttypes"; Description: "扩展格式支持（音频 / 文档 / 压缩包）"; \
      Types: full custom; Flags: checkablealone

[Files]
; 主程序（排除扩展目录，避免重复拷贝）
Source: "..\dist\MediaManager-win-x64\*"; DestDir: "{app}"; \
        Flags: ignoreversion recursesubdirs createallsubdirs; \
        Excludes: "logs\*,logs\*.*,Extensions\*"

; 扩展程序集：只有勾选 exttypes 才拷贝
Source: "..\dist\MediaManager-win-x64\Extensions\*"; DestDir: "{app}\Extensions"; \
        Flags: ignoreversion recursesubdirs createallsubdirs; Components: exttypes
```

要点：
- 主 `[Files]` 必须 `Excludes: "Extensions\*"`，否则扩展会被无条件打进安装包，勾选项就失效了。
- 卸载时 `{app}\Extensions` 随程序目录一起删除（现有卸载逻辑已覆盖程序目录）。
- 打包前 `build/check_privacy.py` 仍要过；新 dll 不能带源路径。

## 9. 设置、安全、兼容

### 9.1 设置页开关

设置 → 格式扩展：

- 「启用音频 / 文档 / 压缩包」三个开关（运行时生效，重启或重扫后应用到扫描）。
- 说明文字：关闭后已入库的项不会删除，只是不再扫描新文件。
- 该开关与"是否安装扩展 dll"是两层：没装 dll 则开关不可见/不可用。

### 9.2 删除 / 还原

`DeletedItem` 表存了 `MediaType`。施工时必须确认：
- 删除新类型文件时，`MediaType` 正确写入（不是默认 `Image`）。
- 还原时按原类型恢复，而不是硬编码图片。
- 缩略图缓存清理路径对新类型安全（没有缩略图时跳过）。

### 9.3 兼容性

- `MediaType` 是 `TEXT`，新值 `"Audio"/"Text"/"Archive"` 与旧值共存，**旧版本打开新库**时：
  - 旧版 `MediaFormat` 不认识这些扩展名，不会扫描；已有行会被 `MediaQuery` 选中但 UI 可能不认识。
  - 建议：升级到 v1.4 前**先备份**；必要时提供"仅显示图片/视频"的兼容查询。
- 版本回退：扩展 dll 删除即可让三类失效，**不破坏**图片/视频数据。

### 9.4 性能

- 扫描：新增类型只多一次字典查询，成本可忽略；但用户可能把整个 C 盘加进来，非媒体文件会显著增加库体积 → 建议 L1 默认只扫描**已启用类型**，并提供"只扫媒体"开关（默认开）。
- 缩略图：L1 用图标，不生成缩略图文件，磁盘/CPU 几乎无额外开销。
- 数据库：`IX_Media_Type` 已存在，按类型筛选很快。

## 10. 测试与验收

### 10.1 单元测试（新增）

- `MediaFormat`：扩展名识别（每个新扩展名至少一个用例）、大小写不敏感、未知扩展返回 null。
- `MediaType` 序列化：写入字符串、旧库值兼容。
- 扫描：混合目录（图片+音频+文档+压缩包）入库数量与类型正确。
- 文本编码：UTF-8 / GBK / UTF-16 各一个用例。
- 压缩包：zip 条目读取（用临时文件构造）。

### 10.2 手工验收清单

- [ ] 添加含 mp3/txt/zip/rar 的文件夹 → 全部入库，分类正确。
- [ ] 音频双击可播，播放/暂停/进度/音量/倍速正常。
- [ ] 文本双击只读预览，中文不乱码，大文件有提示。
- [ ] 压缩包双击列条目，能"用系统程序打开"。
- [ ] 顶部类型筛选：每个选项都只显示对应类型。
- [ ] 发现页只出现图片/视频。
- [ ] 删除/还原三种新类型，数据一致。
- [ ] 安装包勾选 / 不勾选"扩展格式支持"各装一遍，行为符合预期。
- [ ] 旧库（只有图片/视频）升级后无异常。
- [ ] 现有 148 项测试 + 新增测试全绿；`check_privacy.py` 通过。

## 11. 里程碑与工作量

| 里程碑 | 交付物 | 粗估 |

## 12. 风险与回滚

| 风险 | 应对 |
|------|------|
| 扩展 dll 与主程序版本不匹配 | provider 契约保持最小；加载器 try/catch；版本不匹配时跳过并提示 |
| 扩展 dll 崩溃影响启动 | 加载在独立 try/catch；`Assembly.LoadFrom` 失败只记录日志 |
| 新类型稀释发现页 | 发现页 SQL 限定 Image/Video（本版必做） |
| 旧版本打开新库异常 | 升级前备份；必要时加"仅图片/视频"兼容查询 |
| 压缩包/大文本卡 UI | 读取放后台线程；设大小/条目上限 |
| 安装包勾选项失效 | 主 `[Files]` 必须 `Excludes: "Extensions\*"` |

**回滚**：删除 `{app}\Extensions\MediaManager.Extensions.MediaTypes.dll`，重启即可回到"只有图片/视频"；数据库里的新类型行不会主动删除，但不会被扫描/展示（可提供清理脚本）。
